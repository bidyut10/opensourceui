# Product

## Register

brand

## Platform

web

## Users

Primary audience is developers who find a component on Opensource UI, copy the file into their own Next.js app, tweak props, and ship. They want something that looks production-ready without installing a package or learning a design-system API.

When working on individual copy-paste components (forms, cards, inputs), treat the surface as **product** register for that task — design serves the app UI those components will live in. The default for site, marketing, and docs work remains **brand**.

## Product Purpose

Help people find a good-looking React/Next.js component fast and paste it in. Success means more people browsing `/components` and copying code into real projects.

## Positioning

Copy-paste React components that look production-ready without learning a design system.

## Conversion & proof

- Primary CTA: browse and copy components (`/components`)
- Secondary CTAs: GitHub, sponsor (`/sponsor`), contact (`/contact`)
- The line a visitor remembers after 10 seconds: Free forever, copy-paste, production-ready React/Next components
- Belief ladder:
  1. These components are free and open source — and stay free
  2. They look intentional and production-ready, not template-generic
  3. I can copy a single file without adopting a whole system
  4. So I should browse `/components` and paste one into my app
- Proof on hand: Product Hunt / social reviews already on the homepage via `lib/home/testimonials.ts`

## Brand Personality

Clean, confident, practical. Voice stays direct and useful — show the component working, then get out of the way. Craft shows up in spacing, type, and interaction detail, not in hype copy.

## Anti-references

- Generic AI UI: purple gradients, Inter-everywhere monoculture, nested cards, glassmorphism, glow effects
- Heavy enterprise / Material-dense dashboards
- Over-animated “wow” landing pages that prioritize motion theater over clarity

## Design Principles

1. **Copy-paste first** — each component stands alone; no provider maze or theme config tax.
2. **Show, don’t tell** — live demos and real content beat marketing adjectives.
3. **Practice what you preach** — the site and docs should feel as polished as the components visitors copy.
4. **Expert confidence** — restrained surfaces, clear hierarchy, no decorative noise.
5. **Findable craft** — organized by purpose so developers reach a shippable piece quickly.

## Accessibility & Inclusion

Aim for WCAG AA. Respect `prefers-reduced-motion`. Keep text and controls at solid contrast; don’t rely on light gray on tinted backgrounds for body copy or placeholders.
